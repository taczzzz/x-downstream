# 顺流 · X Downstream 1.2.1

**解决「看过 A → 刷新 / 点首页 / 看新 posted → 得到 B → 下刷又回到 A」的旧内容回流。** 保留 X 原生界面和推文操作，也保留到末尾向下续读。无需服务器或 API key。

刷 X 时，刷新出一批新推文，往下刷一会儿却又遇到刚才看过的内容。顺流是一款 Chrome 插件：记住实际浏览过的推文，在下一轮时间线中过滤，让你继续向下看未读内容。

[下载安装包 v1.2.1](https://github.com/taczzzz/x-downstream/raw/refs/heads/main/dist/x-downstream-1.2.1.zip) · [验证记录](docs/TESTING.md)

目前通过「加载已解压的扩展程序」安装，尚未上架 Chrome 应用商店。

## 当前行为

- 首页推文实际进入视野并停留一小段时间后，记录原帖 ID；仅加载到页面但没有看过的内容不会写入已读记录。记录是阅读行为的近似判断，不判断人是否真的读懂。
- 已读记录保存在本机，刷新网页、点击原生首页入口和关闭重开浏览器后继续生效。账号之间隔离；为你推荐和正在关注共享同一账号的已读记录。转帖按原帖 ID 去重。
- 新一轮时间线的首屏和后续分页都过滤已读内容。保留未读推文及其原始字段，由 X 原生渲染器处理正文、回复、点赞、转帖、引用、书签、视频和菜单。
- **posted 完全由 X 原生处理。** 插件不主动点击、不隐藏、不改造提示，也不拦截其回顶行为。你可以照原来的习惯手动点击；它加载的时间线数据同样经过已读过滤。
- 继续向下浏览到末尾时，自动尝试接上未展示内容；没有未读更新时退避等待。页面没有插件新增的批次条、提示、卡片、按钮或样式。
- 底部原生 Retry 可自动尝试恢复，包含通用加载错误和 X 原生「Looks like you lost your connection」断网错误；连续失败退避，最多 5 次。不会点击推文、对话框、侧栏、编辑区或不可见的同名按钮。持续失败保留原生错误。

**记录范围：最近 30 天、每账号最多 5,000 条，最多保留 5 个最近使用的账号。** 刷新前已看过但尚未安装此版本的内容无法补录。扩展弹窗提供「清空已读记录」，清空后刷新 X 首页生效。

## 安装 / 更新

1. 下载上面的 ZIP 并解压，保留解压后的文件夹。
2. 在 Chrome 地址栏打开 `chrome://extensions/`，开启右上角**开发者模式**。
3. 点击**加载已解压的扩展程序**，选择解压目录（该目录内应直接包含 `manifest.json`）。如果下载的是整个仓库，选择仓库中的 `extension` 目录。
4. 刷新已登录的 X 首页，然后照原来的习惯浏览。

更新已有安装：替换原安装目录中的文件，在扩展管理页找到「顺流」，点击**重新加载**，然后**刷新 X 首页**。如果已直接加载本项目的 `extension` 目录，只需重新加载扩展和刷新页面。

Chrome 111 或更新版本。不要同时启用两份顺流。开关和清空记录只在浏览器扩展弹窗内；切换开关会刷新已打开的 X 首页。

## 实现与对抗性修复

插件适配 X 原生首页请求的 `fetch` / 异步文本或 JSON XHR，不重建推文节点或事件监听。请求 URL、query ID、features 和认证请求头沿用原生请求；点赞、回复等写入接口直接透传。

- 首屏按已读 ID 过滤后保留原生排序、完整推文和模块字段；后续未读 entries 调整外层 `sortIndex` 接到末尾，以 `BigInt` 避免精度损失。
- 后台头部刷新不清空当前正在阅读的列表；用户回到顶部重新获取时间线时，重新应用跨刷新已读过滤。
- 本地续读 cursor 在每次重建时间线时保持唯一，避免复用旧请求缓存标识。发送网络请求前解码为服务器 cursor；未知的本页旧 token 也不会发送给服务器。
- 排队的请求可以立即取消；取消一个排队项不会释放其前面仍在执行的任务。账号切换同时取消执行中与排队请求。头部刷新能结束等待中的多个分页任务，避免堵住刷新。
- 同一个 XHR 重新 `open` 会取消旧的模拟请求、回调和计时器，不让旧响应或 timeout 污染新请求。
- 429 冷却覆盖分页、原生 Retry 和后台头部请求；不会把两小时的服务端冷却截断成一小时。空批次等待从 30 秒退避到 120 秒，成功追加后最少间隔 15 秒。
- 已知父会话的 `TimelineAddToModule` 增量保留原生模块字段，将未读回复接到末尾；无法安全解释的结构交给 X 原样处理，不猜测缺失字段。
- 一个 MV3 事件 service worker 仅负责串行写入本地已读记录，避免多个标签页覆盖彼此。它不发网络请求，不常驻轮询。

「新」表示未读或本次页面未展示的内容，不保证全部刚发布，也不跨批次按发布时间重新排序。X 原生接口和渲染器没有面向此插件的稳定兼容承诺。

临时模拟该 X 标签页断网，发现 1.2.0 未识别原生连接丢失文案，网络恢复后停在 Retry。修复为 1.2.1，重新加载扩展后确认实机版本；重复断网，恢复网络后由原生 Retry 处理器自动请求成功、追加推文，未手动点击 Retry、未回顶。临时网络覆盖已撤销。实机结果摘要见[验证记录](docs/TESTING.md)；账号阅读记录及真实页面截图不随仓库发布。

**覆盖边界：** 此次服务器原始响应没有包含采样的旧 A，因此实机结果是「未观察到回流」，强制返回旧 A 的过滤证据来自合成对抗用例；不能把两者混为同一证据。此次未出现可点击的原生 posted 提示（DOM 中的 See new posts 为 aria-hidden），未实测 posted、真实多账号切换或长期运行。已读识别依赖原生推文的时间链接；账号识别优先使用可读的 `twid`，否则使用原生「个人资料」入口。两者都取不到时只保留当前页去重，暂不写跨刷新记录，避免混淆账号。

实站验收：安装更新后先阅读几条 A，再刷新或点击首页 / posted 看到 B，然后继续向下浏览；确认 A 不回流、未读内容仍能出现、原生互动与 posted 的操作保持正常。遇到兼容问题可关闭扩展并刷新恢复原版。

## 权限与数据

唯一声明的权限为 `storage`，内容脚本只匹配 `https://x.com/*` 和 `https://twitter.com/*`。不申请 cookies、全站、tabs 或 downloads 权限。

持久化内容为开关、账号标识（账号 ID 或自身用户名、代理账号 ID）、已读推文 ID 与记录时间。无推文正文、媒体或认证请求头，不上传。当前页面的 session 去重集合、请求头、cursor 和排序状态仍只在内存。清空按钮可删除所有账号的已读记录。

MAIN world 属于网页执行环境，网页本身可以访问或干扰它，不是秘密边界。网页接口权限沿用页面已有登录状态。

## 开发

安装插件不需要 Node.js。开发命令：

```sh
npm install
npx playwright install chromium
npm test
npm run test:browser
npm run test:adversarial
npm run package
npm run preview
```

[本地演示](http://127.0.0.1:4173/home) 为模拟页面；卡片与 CSS 是测试页内容，不打包进插件。正式加载的 MV3 浏览器测试包含完整已读记录功能，本地演示不用于证明账号识别或持久化。

```text
  manifest.json / icons/

demo/                    合成页面，不注入真实 X

dist/                    可安装 ZIP
docs/                    验证说明与合成数据测试报告

```
